# ghostty-console

A Rust console prototype: libghostty-vt terminal state, fish on a PTY, CPU text
rendering to DRM/KMS, evdev/XKB keyboard input and embedded Rime. No Wayland or
X11 server is used. Manual mode starts after a native getty login; the optional
tty6 system frontend displays system login directly inside con.

## Install and configure

```fish
cd ~/mycoding/ghostty-console
fish install.fish
```

The default user installation places the binary in `~/.local/bin` and creates
`$XDG_CONFIG_HOME/ghostty-console/config` (default `~/.config/ghostty-console/config`).
Existing configuration and directory permissions are preserved on reinstall. The
script builds the release binary as the invoking user, validates the bundled config,
and installs the binary atomically. It does not enable services or edit shell PATH.
For a system installation, `fish install.fish --system` uses `/usr/local/bin` and
`/etc/ghostty-console/config`, elevating only the file operations through sudo.
Use `--prefix DIR --config-dir DIR` for another destination; `--no-build` installs
an already-built release binary.

Configuration search order, stopping at the **first existing file**, without merging:

1. `ghostty-console.conf` in the process's starting working directory.
2. `$XDG_CONFIG_HOME/ghostty-console/config`, or `~/.config/ghostty-console/config`.
3. `/etc/ghostty-console/config`.

`--config-file PATH` (or `GHOSTTY_CONSOLE_CONFIG`) explicitly overrides discovery.
The supervisor pins the selected config path for its worker. An invalid/unreadable
higher-priority configuration reports an error rather than falling back silently.

```fish
ghostty-console +show-config
ghostty-console +validate-config
ghostty-console --config-file /path/to/config con
```

The root `ghostty-console.conf` is the commented template and local configuration.
The format follows Ghostty's `key = value` style: whole-line `#` comments, optional
quotes around scalar values, empty values reset defaults, repeated scalar keys use
the last value. Inline comments and unknown keys are errors. Relative resource
paths resolve against the config file's directory; `~/` expands to the user's home.
The `command` value is split into argv with shell-style quoting and executed directly;
pipes, redirects and command substitutions are not interpreted.

Supported settings cover terminal/IME font family and point size, command, timeout,
DRM device, keyboard layout, initial IME state, status visibility, IME display mode,
notification integration (`desktop-notifications = true|false`),
Rime data/schema paths, and foreground/background/cursor colors. See the bundled
file for all keys. Sizes use points at 96 DPI; colors accept `#RRGGBB` or `RRGGBB`.
CLI `--timeout`/`--device` override the config for that launch. Legacy font/source
environment overrides continue to work. This is con's schema, not the entire Ghostty
configuration API; keybindings are currently the documented built-ins.

```ini
font-family = FiraMono Nerd Font Mono
font-size = 13.5
command = /usr/bin/fish --interactive
timeout = 0
status-bar-visible = true
ime-display = inline
```

`ime-display = inline` is the default: an Emacs-like, flat echo line above the fixed
bottom status bar. This echo line is reserved even when Rime is disabled, for transient messages. Preedit and candidates share that single
line; beginning/ending composition does not resize the child. `ime-display = popup`
uses a floating candidate window at the current **VT caret**, moving above it if
there is no room below and clamping at the right edge. Hidden VT caret coordinates
are preserved separately from whether the visible cursor is drawn. Graphical browser
DOM carets are not reported by the terminal protocol; use inline mode for those.
Ctrl+Alt+M changes the mode for the current session without editing the file.

## Build

Requires Rust 1.94+ (Cargo package edition 2024), a C compiler, pkg-config,
librime headers, libghostty-vt headers, libseat, libsystemd, libdrm, libxkbcommon,
FreeType and fontconfig's
`fc-match` and `fc-list`. Fonts are discovered through fontconfig.
The C adapters compile against the installed headers; libghostty-vt APIs vary
between versions, and this prototype targets the version installed on this machine.

```fish
cargo build --release
cargo run -- con --check
cargo run -- preview /tmp/ghostty-console.ppm
cargo test
cargo test --test rime_local -- --ignored
cargo clippy --all-targets -- -D warnings
```

`con --check` loads fonts, Rime and a terminal snapshot, and reports the current
VT/stdin. It does not open seat devices or change tty modes, but may initialize
this application's Rime data directory. `preview` creates an offscreen sample with
Chinese and the existing `wubi98_ci` schema; it does not start a shell or claim a VT.

## Try on tty6

From the existing desktop:

```fish
cd ~/mycoding/ghostty-console
fish scripts/tty6.fish prepare
```

The script needs sudo, refuses a logged-in tty6, and temporarily replaces its
running kmscon service with native getty. Runtime masks on `kmsconvt@tty6` and
`autovt@tty6` prevent logind from restarting kmscon on VT entry. Restore removes
these masks; reboot also clears them. It does not change service enablement.
Press Ctrl+Alt+F6, log in, then:

```fish
cd ~/mycoding/ghostty-console
cargo run --release -- con --timeout 120
```

- Ctrl+Space: toggle Rime (initially English).
- Ctrl+Alt+F1…F12: request a VT switch through the current seat backend.
- Ctrl+Alt+Esc: exit the console worker.
- Ctrl+Alt+I: hide/show the fixed, one-row status bar. IME echo/popup visibility
  follows the selected IME mode independently. Mode badges and responsive hints
  retain their bottom position while candidates appear above them.
- Ctrl+Alt+M: switch between the one-line IME echo area and caret-following popup.
- Ctrl+Alt+N: switch the main window between `*terminal*` and read-only `*Messages*`.
  In `*Messages*`, Up/Down and PgUp/PgDn scroll, Left/Right scroll horizontally,
  Home/End jump to the start/end, and q/Esc return. The child keeps running.
- Ctrl+Alt+H: toggle the full shortcuts overlay, even while the bar is hidden.
  Esc or any non-modifier key closes it without sending that key to the child.
  Modifier releases continue to reach the child to avoid stuck app modifiers.
- Left drag selects visible terminal text. Right-click on a local selection copies
  it and immediately pastes it at the current input position, without adding Enter.
  Middle-click pastes. Ctrl+Shift+C remains copy-only; Ctrl+Shift+V pastes.
- The mouse arrow uses an upright left edge, tip hotspot and cached supersampled
  antialiasing for its fill and outline.
- Applications that request mouse tracking receive clicks, motion and wheel events.
  Hold Shift while dragging to force local text selection. Pixel-rendered browser
  pages use the browser's own selection/right-click menu; those pixels are not
  terminal text. Browser clipboard writes are bridged through OSC 52.
- Text copies use `wl-copy` to reach the existing desktop's Wayland clipboard;
  `wl-paste` handles paste. The display name is inherited or read from the systemd
  user environment. Helpers run asynchronously with deadlines; without a desktop
  clipboard, copied terminal text remains available in the local clipboard.
- In manual mode, `exit` ends con and returns to the outer getty shell. In system
  login mode, it logs out and starts a fresh login screen.
- The parent ends the trial after 120 seconds, sends SIGTERM, then SIGKILL if the
  worker does not exit within two seconds. `--timeout 0` disables this deadline.

The parent saves keyboard/display modes and termios before starting the worker,
and restores them after worker exit, including worker crashes. This is not a
recovery guarantee for kernel/driver hangs or simultaneous loss of both processes.
Logs go to `$XDG_STATE_HOME/ghostty-console/con.log`, defaulting to
`~/.local/state/ghostty-console/con.log`.

After the test, leave the tty6 login shell with `exit`, return to tty1, then:

```fish
fish scripts/tty6.fish restore
```

`--device /dev/dri/cardN` selects a card; otherwise the first card is used.
Only one connected output is drawn. Unsupported display geometry changes during
resume cause an error/exit rather than a terminal reset. The trial helper does
not install autologin or persistent login integration. If the system frontend is
already deployed, use its deployment section instead of the temporary restore helper.

## Manual mode architecture

```text
native getty -> login shell -> supervisor (saved tty state, deadline)
                                -> console worker
                                     libseat/logind -> DRM/KMS + evdev
                                     evdev -> XKB -> reserved shortcuts
                                                   -> Rime -> commit
                                                   -> Ghostty key encoder
                                                        -> PTY -> fish
                                     PTY -> libghostty-vt -> cell snapshot
                                         -> CPU font renderer -> DRM buffers
                                     Rime -> preedit/candidate overlay
```

The worker uses a single-threaded poll loop. PTY reads are bounded per iteration
so child output cannot indefinitely postpone the seat handshake. Inactive sessions
continue reading the PTY but stop using display/input devices. Scrollback and PTY
write queues are bounded. Text rendering currently caps each grapheme at 63 UTF-8
bytes and substitutes U+FFFD for larger clusters.

Modules: `console` (supervision/event loop), `display` (DRM), `keyboard` (evdev/XKB),
`terminal` (Ghostty adapter), `pty`, `renderer`, `rime`, `ime` (lazy personal input),
`config`, `seat` (backend selection), `broker` (native tty6 devices),
`login_service` / `login_gate` / `session` (authentication lifecycle). Small C bridges
use native headers instead of duplicating versioned C structures in Rust.

Input events intentionally use evdev rather than libinput: this machine's
libinput links Lua 5.4, while its Rime Lua plugin links Lua 5.5; loading both into
one process caused a reproducible Lua panic. evdev handles keyboard input without
that dependency. Relative mice are supported; absolute touchpad/touch input is not yet handled.

## Fonts

The primary family/size come from con's `font-family` / `font-size` configuration.
When unset, the old main-file Ghostty font settings are used as a compatibility
fallback, finally defaulting to FiraMono Nerd Font Mono at 18 pixels. Ghostty includes
and conditional settings are not interpreted.
An installed exact family is pinned before consulting Fontconfig's fallback list;
this avoids user substitution rules replacing specialized fonts. FreeType rasterizes
with normal grayscale hinting. Cell width and baseline come from actual metrics;
line height accommodates both terminal and IME fonts. Missing characters are
resolved lazily through Fontconfig's sorted chain and other installed fonts using
charset coverage. Chinese follows the terminal's monospace fallback preferences.

The IME has a separate font and glyph cache. `ime-font-family` / `ime-font-size`
override the `Font` fallback from `~/.config/fcitx5/conf/classicui.conf`
(this machine uses `98WB-2 12`). Set
`GHOSTTY_CONSOLE_IME_FONT_FAMILY` and `GHOSTTY_CONSOLE_IME_FONT_SIZE` (pixels) to
override. The candidate bar advances by actual glyph metrics, not terminal cells.
This distinction is essential: 98WB five-stroke root symbols and Nerd Font icons
reuse some of the same private-use Unicode codepoints. Terminal cells keep the
Ghostty-provided widths and the terminal's font priority. Neither global fontconfig
nor fcitx5/Rime configuration is modified.

Startup logs record the requested/resolved family, file, collection index, pixel
size and cell geometry. Override directly with fish-compatible environment values:

```fish
env GHOSTTY_CONSOLE_FONT_FAMILY="FiraMono Nerd Font Mono" GHOSTTY_CONSOLE_FONT_SIZE=22 cargo run --release -- con
```

The environment size is in pixels. A configured Ghostty `font-size` is interpreted
as points at 96 DPI; when neither size is set the default remains 18 pixels. This
is a fixed scale for the prototype, not per-monitor DPI detection. FreeType alone
does not provide Ghostty's full shaping and style selection pipeline. Single color-bitmap glyphs are supported,
but multi-codepoint emoji composition and complex script shaping remain incomplete.

## Existing Rime configuration

Source defaults to `$XDG_DATA_HOME/fcitx5/rime` (or `~/.local/share/fcitx5/rime`).
Override with `GHOSTTY_CONSOLE_RIME_SOURCE`. Compiled dictionaries are read from
its `build/` directory. Text configuration and auxiliary Lua/OpenCC files are
seeded once into `$XDG_DATA_HOME/ghostty-console/rime`; reverse dictionaries are
copied there for custom translators. Existing copies are not overwritten; source
configuration updates need an explicit future refresh/redeployment mechanism.

The app maintains separate learning databases and locks its data directory against
concurrent app instances. Live fcitx5 LevelDB databases are never opened/copied;
their existing learned vocabulary is not imported. The last selected source schema
is used by default. System Rime plugins, including Lua, load normally.

```fish
cargo run -- rime-probe py nihao
cargo run -- rime-probe wubi98_ci wqvb
```

Both commands append Space and should finish with `commit="你好"`.
`rime::Rime::process_key` returns owned preedit, UTF-8 byte cursor/selection offsets,
candidates, comments, page/highlight and committed text. Commits go to the PTY;
unconsumed keys go to Ghostty's encoder. Releases of IME-consumed presses are not
forwarded to the child. Toggling the IME or leaving the VT cancels composition.

## Browser validation

The installed `terminal-browser` can be exercised without claiming a VT:

```fish
cargo run --release --example browser_check -- /tmp/con-browser.ppm
```

Set `GHOSTTY_CONSOLE_KEEP_BROWSER_PROFILE=1` to keep that isolated profile and
its logs after the browser is shut down; the check prints the diagnostics path,
elapsed time, and whether the CLI child exited. This does not retain or stop any
real browser profile.

Known intermittent result: one retest stalled on an initial black browser frame;
four subsequent runs passed, including one during VT switching. The startup stall
has not been attributed or ruled out; keep diagnostics when reproducing it.

The check uses an isolated temporary browser profile/runtime and a local HTML page.
It verifies changing image frames, resizes the browser through PTY/window reports,
clicks a page button through encoded mouse events, then receives the selected text
through the browser's clipboard protocol. It never writes the real desktop clipboard
and shuts down only its isolated browser instance. Physical evdev routing, DRM
presentation and desktop clipboard ownership still need a real-console check.

Kitty image storage is limited to 64 MiB. Visible image snapshots share cached pixel
buffers and are invalidated by storage/image/generation; reads of terminal-owned
pixels never outlive a mutation. File/shared-memory loading uses libghostty-vt's
protocol implementation. This is a Kitty image frontend, not a Sixel renderer.

## Buffers, windows and messages

The structure follows Emacs' distinction between content, the window showing it,
the mode line, and the echo area. References:
[Buffers](https://www.gnu.org/software/emacs/manual/html_node/emacs/Buffers.html),
[Echo Area](https://www.gnu.org/software/emacs/manual/html_node/emacs/Echo-Area.html),
[Mode Line](https://www.gnu.org/software/emacs/manual/html_node/emacs/Mode-Line.html).
The physical order keeps con's requested layout: main window, echo line, bottom mode line.

- `*terminal*` retains the Ghostty VT and live PTY. Switching to another buffer
  does not restart, stop, or resize the shell. Programs can keep producing output.
- `*Messages*` keeps up to 1,000 messages in memory for this con instance; it is
  read-only and not written to disk. Each message retains source, local timestamp
  and line breaks. Long lines can be viewed with horizontal scrolling. The view
  retains its scroll position across buffer switches and follows new messages
  only when already at the end. Console readiness, clipboard results and
  notifications use this same message route. Input-method preedit is transient
  and is not added to the message history.
- The echo area displays the latest message for five seconds. Inline Rime
  composition takes priority; arriving notifications still enter `*Messages*`.
  The line stays reserved so arrivals do not resize full-screen applications.
  Popup Rime uses the VT caret in the terminal window; it is hidden while the
  main window shows `*Messages*`.
- The mode line describes the selected buffer and mode. For the terminal it
  includes caret position and dimensions when space permits; for `*Messages*`
  it shows the read-only state and navigation hints. Ctrl+Alt+I toggles this
  mode line independently of the echo area.

### Notifications without a desktop

A native VT and PTY do not launch a desktop. con connects to the user's D-Bus
session bus (normally provided by systemd/PAM, independent of a compositor).
The PTY child receives that bus address, including when the getty shell did not
export `DBUS_SESSION_BUS_ADDRESS`.

When no notification server exists, con serves `org.freedesktop.Notifications`
and accepts `notify-send` directly. It supports plain text bodies and standard
server information/capability queries; actions, icons, and notification markup
are not rendered. The echo area's five-second lifetime is fixed; replacement IDs
are accepted, while `*Messages*` remains an append-only history. Closing a
notification does not delete its history entry. This is an initial text notification
implementation, not a complete desktop notification center.

When a desktop notification server already exists, con does not replace it.
It uses a separate D-Bus monitor restricted to `Notify` calls, mirroring those
messages into the same buffers. A later desktop server may replace con's native
service. This mirrors notifications on the **same user session bus**, not another
user's bus. If bus policy refuses monitoring, the native service still works when
con owns the notification name; the failure is recorded in `*Messages*`.
No graphical session or root privileges are needed.

```fish
# Run inside con's fish; no desktop required.
notify-send --app-name=build '构建完成' 'cargo build 已完成'
# Ctrl+Alt+N opens *Messages*.
```

`desktop-notifications = false` disables both notification serving and mirroring.
The message buffer and clipboard feedback remain available. The current buffer
layer is deliberately small: terminal and messages, one main window, no general
text editing, arbitrary split windows, or Lisp runtime.

## Legacy deployment: start con after a getty login

This alternative is not the direct-login frontend described below. Do not combine
the two; the direct-login installer removes this fish hook.

```fish
fish install.fish
# Install the login hook; it runs once at fish's first prompt, only on native tty6.
install -m 644 scripts/tty6-login.fish ~/.config/fish/conf.d/ghostty-console-tty6.fish
sudo fish --no-config scripts/tty6-persist.fish
```

The persistent script keeps a one-time backup of the original tty6 unit links in
`/var/lib/ghostty-console/tty6-before-deploy`, masks the tty6 kmscon instance,
points only `autovt@tty6` at native getty, and adds native tty6 to getty.target.
Other VTs retain their existing configuration. The login hook runs installed
`~/.local/bin/ghostty-console con --timeout 0`; Ctrl+Alt+Esc returns to the login
shell without immediately relaunching con. Set `GHOSTTY_CONSOLE_NO_AUTOSTART`
before fish starts to bypass the hook, or remove that conf.d file to disable it.
The temporary `scripts/tty6.fish restore` is for trial setup only; it does not undo
this persistent deployment. Restoring the backed-up tty6 links requires root and
should be done after logging out of tty6.

## Login directly inside con (tty6 system frontend)

```fish
cargo build --release --locked
# Log out of tty6; run from another VT or the desktop.
sudo fish --no-config scripts/install-tty6-login.fish lorangeve
```

The root-owned system frontend displays the system login prompts inside con.
PAM remains responsible for authentication; there is no autologin and no custom
password verifier. The configurable `command` is ignored in login-service mode.
`login -p -s /usr/local/libexec/ghostty-console-login-shell` authenticates first,
then runs a small root-installed shell barrier. That barrier waits until the
supervisor has persisted the exact PAM scope identity, then execs the account's
original configured shell as a login shell. Account shells such as nologin/false
remain authoritative.

### Login and process boundaries

- The root supervisor owns the login PTY and a native VT broker explicitly bound
  to **tty6** using VT_PROCESS. It does not use seatd or infer its VT from whichever
  console happens to be active. The existing manual `con` mode still uses logind.
- Before authentication, the frontend runs as the dedicated, non-login system
  account `ghostty-console`. Its home is root-owned. Fontconfig uses system
  configuration; personal fonts, Rime/Lua, clipboard and notification integration
  are not initialized. A user's broken/locked Rime data cannot block login.
- The shell barrier connects to a root-owned Unix socket. The supervisor validates
  SO_PEERCRED plus the PAM session's actual leader against its own login child,
  and records the scope's invocation ID before acknowledging the barrier. An
  unrelated desktop process cannot acknowledge or claim a login with a supplied
  username/session string. No password is sent through this gate.
- After authentication, a fresh frontend replaces the greeter and drops to the
  authenticated account before loading personal components. UID/GID privileges
  and capabilities are discarded, and no-new-privileges applies to the frontend;
  it does not apply to the independently created authenticated login shell.
  The terminal view starts afresh at this boundary and asks the foreground
  application to redraw with SIGWINCH. Root logins retain the system-only frontend
  and do not load personal Rime or desktop integration.
- Rime is lazy: it starts on the first activation, or when initially enabled after
  authentication. Initialization errors leave English input usable and are shown
  in `*Messages*`. Private-use font roles remain separate after authentication.

### Device and session lifecycle

The device broker has no public device-control socket. The frontend inherits
private datagram channels and receives descriptors with SCM_RIGHTS. Requests are
limited to numeric `/dev/dri/cardN` and `/dev/input/eventN` character devices,
closing those handles, acknowledging tty6 release, and switching valid VTs.
Descriptor counts, packet sizes and inherited descriptor lifetimes are bounded.
The root broker does not parse terminal output, fonts, or input-method scripts.
System frontends detach from the native controlling tty and replace stdin with
/dev/null before dropping privileges. Only the broker owns native VT mode changes;
personal extensions cannot replace its VT_PROCESS owner through an inherited tty.

On release, DRM master and evdev access are revoked before the frontend is
notified. A renderer which fails to acknowledge cannot hold VT switching forever.
DRM handoff retries and device revocation are treated as transitions rather than
logging the user out. Temporarily missing input devices are rescanned, including
when a VT switch interrupts the first keyboard scan. This frontend currently
assumes the machine's single seat0 setup.

The supervisor records its own PAM session scope and invocation identity in
`/run/ghostty-console/tty6-session`. Normal exit explicitly terminates that scope.
ExecStopPost performs the same verified cleanup if the supervisor is killed.
Cleanup and the authenticated shell barrier bypass renderer configuration parsing,
so a broken configuration cannot disable emergency cleanup.
The shell barrier prevents user shell startup before that record is durable.
Cleanup never terminates the entire user slice, another VT's session, or the user
manager. User services intentionally launched outside this session scope are not
covered. Detached jobs **within this login scope** are terminated on logout or
frontend termination, even when the global KillUserProcesses setting is disabled.

The frontend checks termios immediately before routing input, copying/pasting or
handling asynchronous paste results. Canonical no-echo prompts suppress Rime and
paste; errors reading the mode fail closed. Entering a private input state clears
preedit, pending input and stale clipboard generations. Raw-mode applications
remain usable: arbitrary custom password widgets cannot be inferred solely from
termios and are not claimed to be detected.

### Deployment and validation

The installer removes the earlier fish autostart hook. The system binary is
`/usr/local/bin/ghostty-console`; the service configuration is explicitly pinned to
`/etc/ghostty-console/config`. Existing configuration is preserved. Only tty6's
unit links change, with the previous links backed up under
`/var/lib/ghostty-console/prelogin-before-deploy`. A startup failure falls back to
native getty. Ctrl+Alt+F1 returns to the desktop; logging out or Ctrl+Alt+Esc returns
to a clean login screen. Do not use the old temporary tty6 restore helper to undo
this persistent service deployment.

Validation includes the Rust suite, clippy, real installed fonts/Rime checks, an
isolated PAM scope test whose detached job ignored HUP/TERM, and live tty6 login /
frontend handoff / logout smoke checks. The supervisor was also forcibly killed
after authentication: ExecStopPost removed the captured scope and detached test
job, while tty1 remained active. Tests never print the login password or terminal
contents. The reusable isolated scope test supplies no credentials:

```fish
cargo build --release --example session_cleanup_check
sudo systemd-run --wait --pipe --collect target/release/examples/session_cleanup_check lorangeve
```
